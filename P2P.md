# P2P-стек Гипер Базы для звонилки

Контекст: в `giper/baza` (ветка `p2p`, смержено) теперь есть полный P2P-стек. Этот файл — что из него использовать здесь и почему.

## Кубики базы

- **`giper/baza/port/webrtc`** — общая WebRTC-кухня:
  - `$giper_baza_port_webrtc` — порт над RTCDataChannel, после открытия регистрируется в `yard.peers` и синкает все общие ленды напрямую, минуя мастеров.
  - `$giper_baza_port_webrtc_propose()` / `_accept( offer )` — возвращают `{ rtc, channel, sdp }`; `rtc` и `channel` доступны синхронно, `sdp` — промис полной строки после non-trickle сбора ICE.
  - `$giper_baza_port_webrtc_finish( rtc, answer )` — применить ответ.
  - TURN/STUN: `$giper_baza_port_webrtc.ice = [ ... ]`.
- **`giper/baza/room`** — знакомство через саму базу (нужен доступный мастер):
  - `$giper_baza_room_grab()` — создать комнату (ленд с post-for-all).
  - `$giper_baza_room.join( land_id )` — подключиться; держать `run()` востребованным (из mem, который читает рендер); `mates()` — кто онлайн, `ports` — прямые порты.
  - Сигналы едут юнитами через мастера, роль offerer детерминирована (меньший лорд).
- **`giper/baza/hand`** — ручное рукопожатие БЕЗ мастера (оффлайн hotspot, наш вело-кейс):
  - Сторона A: `const offer = await hand.proposal()` — строку в QR.
  - Сторона B: `const answer = await hand.answer( offer )` — строку обратно.
  - Сторона A: `await hand.finish( answer )` — канал открыт.
  - `hand.port()` — реактивный статус, `hand.reset()` — новая попытка (новый QR).
  - Камера, сканер и рендер QR — на нашей стороне, база гоняет только строки.

## Рецепт звонка

Голос — это не DataChannel, а **audio-треки в том же RTCPeerConnection**:

1. Устанавливаем соединение через room (онлайн) или hand+QR (оффлайн).
2. `getUserMedia({ audio: true })` → `rtc.addTrack( track, stream )` (до createOffer, чтобы трек попал в SDP; либо renegotiation).
3. `rtc.ontrack` → `<audio autoplay>` (на iOS автоплей аудио разрешён после жеста пользователя — старт звонка кнопкой это покрывает).
4. DataChannel рядом остаётся для данных: пресенс, мьют-статус, чат — можно прямо лендом через базу (порт уже в `yard.peers`).

## Ограничения, о которых помнить

- **Радиус hotspot** на открытом воздухе — десятки метров. Отстала на сотню — канал порвётся; после сближения нужен новый handshake (`hand.reset()` + QR) либо room, если появился мастер.
- **Symmetric NAT** без TURN не пробивается — для оффлайн-LAN неактуально (host-кандидаты), для интернет-звонков задать TURN в `$giper_baza_port_webrtc.ice`.
- **Локальный мастер** (если хочется room без интернета): `npx mam giper/baza/app/run` → один файл `giper/baza/app/run/-/node.js` → `node node.js port=9090` (Termux/Android нативно; на iPhone только iSH — медленно и фон убивается).
- **Тест двух лордов на одной машине**: открыть страницу с `localhost` и `127.0.0.1` — разные origin, разные localStorage, разные лорды. Логи синка: аргумент `giper_baza_log=1` (разделитель аргов в хеше — `/`).

## Почему не auto-mesh

Для звонилки комната на пару человек — полный mesh из одного линка, room-API покрывает всё. Auto-mesh (сам соединяться со всеми пирами каждого ленда) нужен большим живым аудиториям одного ленда и стоит presence-инфраструктуры, лимитов соединений и приватности (IP всем пирам). Если когда-то понадобится — строится поверх room (`room_of(land)` по хешу + кольцо лордов), ничего в звонилке переделывать не придётся.
